# 02｜系统架构与技术选型

## 1. 架构概览

采用前后端分离的单体 Web 架构，不拆微服务。前端 Vue SPA 负责展示和交互；后端 Express 提供 REST API；MySQL 存储用户、信息、图片元数据和申请；本地目录存储图片文件。

```text
浏览器
  │
  ▼
Vue 3 + TypeScript + Vite (5173)
  ├── Vue Router：路由与登录守卫
  ├── Pinia：当前用户与页面状态
  ├── Axios：统一请求、Token、错误处理
  └── Element Plus + SCSS：交互控件和视觉规范
  │ HTTP / JSON / multipart
  ▼
Express 5 + TypeScript (3000)
  ├── routes：路由定义
  ├── middleware：鉴权、校验、错误处理、上传
  ├── controllers：HTTP 输入输出
  ├── services：业务规则和事务
  ├── repositories / Prisma：数据访问
  └── /uploads：图片静态资源
  │
  ├──────────────► MySQL 8.4 (3306)
  └──────────────► 本地 uploads/ 目录
```

## 2. 为什么选择这套方案

- 两人分工边界明确：B 管理 Vue 前端，A 管理 Express 后端。
- 前后端都使用 TypeScript，减少字段理解和类型转换成本。
- Express 单体适合 14 天项目，不需要维护多个服务。
- MySQL 关系模型适合用户—信息—申请之间的外键约束。
- Prisma 负责 schema 和迁移，避免两人手工维护不同数据库结构。
- Element Plus 用于表单、弹窗、分页和提示等控件，但页面布局和视觉样式必须主动定制。

## 3. 模块边界

### 前端模块

- `auth`：注册、登录、退出、会话状态。
- `home`：首页摘要和快捷入口。
- `posts`：信息广场、详情、发布、编辑。
- `applications`：提交申请、处理申请、状态反馈。
- `profile`：我的发布、我的申请、收到的申请。
- `admin`：管理员信息管理（P1）。
- `shared`：导航栏、页脚、空状态、加载骨架、状态徽标、图片预览等通用组件。

### 后端模块

- `auth`：注册、登录、当前用户、JWT。
- `users`：个人资料和用户摘要。
- `categories`：分类查询。
- `posts`：信息 CRUD、列表搜索筛选。
- `applications`：申请提交、审核、完成、状态流转。
- `files`：图片上传、类型和大小验证。
- `admin`：隐藏/恢复信息（P1）。

## 5. 后端分层规则

- `routes` 只声明路径、HTTP 方法和中间件。
- `controllers` 读取参数、调用 service、返回统一响应，不写复杂业务逻辑。
- `services` 实现权限、状态机、事务和业务规则。
- Prisma 访问只放在 service 或 repository，不在多个 controller 中复制 SQL。
- 全局 error middleware 统一格式化错误。
- 请求参数使用 Zod 校验；校验失败返回 HTTP 400 和业务码 `40001`。

## 6. 前端结构规则

- 页面视图只负责组合组件和绑定数据；复杂交互拆成组件或 composable。
- API 请求集中在 `src/api/`，页面不得直接拼写 `axios.get()`。
- 统一 API 类型放在 `src/types/`，不要在多个页面重复定义同一个 Post 类型。
- 登录状态放 Pinia；Token 按约定存 `sessionStorage`。
- 状态标签映射集中定义，不在各页面硬编码不同中文名称。
- Mock 与真实请求共用同一份 TypeScript 类型和返回结构。

## 7. 质量与工程配置

- TypeScript 严格模式开启；禁止无理由使用 `any`。
- 前端提交前执行 lint、typecheck、build。
- 后端提交前执行 lint/typecheck/test/build（以仓库配置脚本为准）。
- 格式采用 2 空格缩进、UTF-8、LF、文件末尾换行。
- 统一使用 npm，提交 `package-lock.json`，不混用 yarn/pnpm。
- 版本依赖使用兼容稳定版本；不要安装 Alpha、Beta 或 RC 预发布版本。
