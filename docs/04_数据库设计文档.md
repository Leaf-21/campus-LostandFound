# 04｜数据库设计文档

- 数据库：MySQL 8.4 LTS
- ORM：Prisma
- 字符集：`utf8mb4`
- 时间：数据库按 UTC 存储或由 Prisma DateTime 统一处理，API 输出 ISO 8601；前端按 Asia/Shanghai 显示。项目开发统一使用同一时区配置。

## 1. ER 关系概览

```text
User 1 ───── N Post
User 1 ───── N Application (applicant)
Post 1 ───── N PostImage
Post 1 ───── N Application
Category 1 ─ N Post
```

## 2. 实体表

### 2.1 `users`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| account | VARCHAR(30) | NOT NULL，UNIQUE |
| password_hash | VARCHAR(255) | NOT NULL，bcrypt 哈希 |
| nickname | VARCHAR(40) | NOT NULL |
| avatar_url | VARCHAR(500) | NULL |
| phone | VARCHAR(30) | NULL，私密字段 |
| email | VARCHAR(120) | NULL |
| role | ENUM(USER, ADMIN) | 默认 USER |
| created_at | DATETIME(3) | 创建时间 |
| updated_at | DATETIME(3) | 更新时间 |

### 2.2 `categories`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| code | VARCHAR(30) | UNIQUE，例如 DIGITAL |
| name | VARCHAR(40) | UNIQUE，分类名称 |
| sort_order | INT | 排序 |
| is_active | BOOLEAN | 默认 true |

首版分类固定为：数码产品、证件卡类、书籍文具、生活用品、衣物配饰、其他。

### 2.3 `posts`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| publisher_id | CHAR(36) | FK → users.id，NOT NULL |
| category_id | CHAR(36) | FK → categories.id，NOT NULL |
| post_type | ENUM(LOST, FOUND) | NOT NULL |
| title | VARCHAR(100) | NOT NULL，应用层限制 2–50 字 |
| description | TEXT | NOT NULL，应用层限制 10–1000 字 |
| location | VARCHAR(120) | NOT NULL |
| occurred_at | DATETIME(3) | 丢失/拾获时间 |
| reward | VARCHAR(255) | NULL |
| status | ENUM(OPEN, PROCESSING, RESOLVED, CLOSED, HIDDEN) | 默认 OPEN |
| created_at | DATETIME(3) | 创建时间 |
| updated_at | DATETIME(3) | 更新时间 |
| resolved_at | DATETIME(3) | NULL，完成时间 |

推荐索引：`(post_type, status, created_at)`、`(category_id, status)`、`(publisher_id, created_at)`、`(location)`。标题/描述关键词首版使用 LIKE 查询即可，不引入全文搜索服务。

### 2.4 `post_images`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| post_id | CHAR(36) | FK → posts.id，删除 Post 时级联删除元数据 |
| url | VARCHAR(500) | NOT NULL |
| sort_order | INT | 默认 0 |
| created_at | DATETIME(3) | 创建时间 |

单条 Post 最多 5 张图片。图片文件保存在 `backend/uploads/`，数据库只存可访问 URL，不存二进制。

### 2.5 `applications`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| post_id | CHAR(36) | FK → posts.id，NOT NULL |
| applicant_id | CHAR(36) | FK → users.id，NOT NULL |
| application_type | ENUM(CLAIM, CLUE) | NOT NULL |
| details | VARCHAR(1000) | NOT NULL，应用层限制 10–500 字 |
| status | ENUM(PENDING, ACCEPTED, REJECTED, CANCELLED, COMPLETED) | 默认 PENDING |
| review_note | VARCHAR(500) | NULL |
| created_at | DATETIME(3) | 创建时间 |
| updated_at | DATETIME(3) | 更新时间 |
| reviewed_at | DATETIME(3) | NULL |
| completed_at | DATETIME(3) | NULL |

推荐索引：`(post_id, status)`、`(applicant_id, created_at)`、`(post_id, applicant_id)`。同一用户同一信息的有效申请约束由 service 在事务中检查（同一用户同一信息只能有一条 PENDING/ACCEPTED）。

### 2.6 `admin_actions`

> 2026-11-19 新增（docs/13 D9 落地）：记录管理员隐藏/恢复操作与原因，满足 docs/05 §10.2「后端应记录管理员操作和原因」。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | CHAR(36) | PK，UUID |
| admin_id | CHAR(36) | FK → users.id，NOT NULL |
| target_type | VARCHAR(30) | 操作对象类型，首版固定 `POST` |
| target_id | CHAR(36) | 操作对象 ID |
| action | VARCHAR(20) | `HIDE` | `RESTORE` |
| reason | VARCHAR(200) | NULL，操作原因 |
| created_at | DATETIME(3) | 操作时间 |

索引：`(target_type, target_id, created_at)`、`(admin_id, created_at)`。

**日志只插入，不更新、不删除**，用于审计追溯。

### 2.7 `posts.previous_status`（新增列）

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| previous_status | ENUM(OPEN, PROCESSING, RESOLVED, CLOSED, HIDDEN) | NULL，默认 NULL |

隐藏信息时保存原状态，恢复时精确还原（docs/05 §10.3）。非隐藏状态下该列为 NULL，不影响既有查询。

## 3. 关系与删除规则

- User 与 Post：一对多；用户不提供硬删除功能，避免历史信息孤儿。
- User 与 Application：一对多；申请保留历史。
- Post 与 PostImage：一对多；信息元数据删除可级联，但首版不提供硬删除。
- Post 与 Application：一对多；保留历史，不物理删除。
- Category 与 Post：一对多；已使用分类不允许删除，只能停用。

## 4. 状态枚举

### Post.status

| 值 | 中文 | 含义 |
|---|---|---|
| OPEN | 等待中 | 可提交申请 |
| PROCESSING | 处理中 | 有申请被接受，正在联系/交接 |
| RESOLVED | 已完成 | 已找回或已归还 |
| CLOSED | 已关闭 | 发布者主动关闭 |
| HIDDEN | 已隐藏 | 管理员隐藏违规信息 |

### Application.status

| 值 | 中文 | 含义 |
|---|---|---|
| PENDING | 待处理 | 等待发布者审核 |
| ACCEPTED | 已接受 | 发布者确认申请有效 |
| REJECTED | 已拒绝 | 发布者拒绝或其他申请被选中 |
| CANCELLED | 已撤回 | 申请者主动撤回（P1） |
| COMPLETED | 已完成 | 交接完成 |

## 5. 事务要求

接受申请必须在单个数据库事务内：校验 Post 为 OPEN、目标 Application 为 PENDING、操作者为 Post 发布者；将目标申请改为 ACCEPTED；将同 Post 其余 PENDING 改为 REJECTED；将 Post 改为 PROCESSING。事务失败时不得出现“申请已接受但 Post 仍 OPEN”的半成功状态。

完成交接必须在事务内：校验操作者是发布者、Application 为 ACCEPTED、Post 为 PROCESSING；将 Application 改为 COMPLETED、Post 改为 RESOLVED，设置完成时间。

## 6. Seed 数据要求

必须提供 `prisma/seed.ts`：

- 插入 6 个固定分类。
- 创建至少 2 个演示普通用户、1 个管理员（账号和密码从环境变量读取，不将真实密码硬编码提交）。
- 插入不少于 10 条示例信息，覆盖 LOST/FOUND、不同类别、不同状态、图片有无。
- 至少准备一组可演示的申请数据。
- Seed 应可重复执行（upsert），不得每次运行重复插入。

## 7. Prisma 模型映射注意

对外 API 使用 camelCase（如 `createdAt`），数据库表名可用 snake_case（如 `created_at`），在 Prisma 中通过 `@map` / `@@map` 映射。所有 ID 统一 UUID 字符串。业务状态由后端 service 控制，前端不可直接写入 Post/Application 状态。
