# 00｜开发前统一决策与项目约定

- 版本：V1.0
- 确认日期：2026-11-15
- 开发日期：2026-11-16 至 2026-11-29
- 适用人员：成员 A、成员 B
- 状态：**本文件作为开发基线，编码开始后默认冻结**

## 1. 项目目标和评分导向

本项目交付校园失物招领 Web 平台。评分由项目意义 5%、交互设计 90%、场景视频 5% 构成。场景视频已完成，不再安排制作任务。开发与验收应主要围绕交互设计展开，重点检查视觉美观、流程与布局合理、信息组织易用、校园场景匹配度。

**总目标：** 让一名校园用户可以在不接受口头指导的情况下，完成“浏览信息—查找目标—查看详情—提交认领/线索—发布者处理—确认归还/找回”的完整流程。

## 2. 技术栈冻结

| 类别 | 固定选择 | 决策理由 |
|---|---|---|
| 前端语言/框架 | TypeScript + Vue 3 | 组件化、上手快，适合两人并行 |
| 前端构建 | Vite | 开发启动快，构建配置简洁 |
| UI 基础库 | Element Plus | 表单、对话框、消息、分页等成熟组件 |
| 样式 | SCSS + CSS Variables | 保留定制视觉的自由度，不把页面做成默认后台模板 |
| 图标 | lucide-vue-next | 图标风格统一 |
| 路由/状态 | Vue Router 4 + Pinia | 路由守卫和共享用户状态 |
| 请求 | Axios | 统一拦截器、错误处理、Token 注入 |
| 后端 | Node.js 26 LTS + Express 5 + TypeScript | 前后端同语言，降低两人协作成本 |
| 参数校验 | Zod | 请求字段校验、类型约束 |
| 数据库 | MySQL 8.4 LTS | 关系数据、事务和外键约束 |
| ORM | Prisma | 模型定义、迁移和类型安全 |
| 认证 | JWT + bcrypt | 轻量登录方案，满足课程项目需求 |
| 上传 | Multer + 本地 uploads 目录 | 两周内避免引入对象存储配置 |

未经双方批准不得替换框架、数据库、ORM、认证方式或 UI 基础库。具体版本写入 `package-lock.json`；禁止使用 Node.js Alpha 或奇数试验线。

## 4. 产品范围冻结

### 4.1 P0 必须交付

- 注册、登录、退出、获取当前用户。
- 首页和信息广场。
- 寻物/招领类型切换。
- 关键词搜索、分类筛选、地点关键词筛选、状态筛选、最新/最早排序、分页。
- 信息详情、图片展示、发布者公开信息。
- 发布寻物/招领信息，最多 5 张图片。
- 编辑本人处于 `OPEN` 状态的信息。
- 对招领信息提交认领申请，对寻物信息提交线索。
- 发布者查看收到的申请并接受/拒绝。
- 我的发布、我提交的申请、我收到的申请。
- 接受申请后进入处理中；完成交接后标记为已找回/已归还。
- 加载、空数据、失败、成功、表单校验、重复提交保护等交互状态。

### 4.2 P1 有余力再做

- 管理员查看、隐藏、恢复违规信息。
- 修改头像、电话等个人资料。
- 申请人撤回待处理申请。
- 发布者关闭未处理的信息。

### 4.3 本轮明确不做

站内即时聊天、短信/邮件验证码、学校统一身份认证、地图定位/GPS、支付/悬赏支付、AI 图片识别、推送通知、复杂数据大屏、多校区多租户。不得为了“看起来功能多”临时加入这些内容。

## 5. 两人职责固定

| 成员 | 主责 | 必须交付 |
|---|---|---|
| A：后端负责人 | API、数据库、认证、业务规则、文件上传、部署配置 | 后端可启动、迁移/Seed、接口响应符合契约、API 可联调 |
| B：前端负责人 | UX/UI、页面、组件、路由、状态管理、Mock、前端构建 | 页面可运行、核心流程可操作、适配桌面/移动宽度 |
| 双方 | 需求冻结、接口评审、PR 互审、联调、测试、验收 | 每天同步进度，接口变更双方确认 |

B 是 UI/UX 主负责人，但 A 必须参加交互流程评审；A 是后端负责人，但 B 必须理解核心数据结构和 API。

## 6. 全局字段和格式规则

- API 所有路径统一 `/api/v1` 前缀。
- 数据交换使用 JSON；图片上传使用 `multipart/form-data`。
- JSON 字段统一使用 `camelCase`；数据库字段使用 Prisma/SQL 对应命名，不允许前端直连数据库。
- ID 对外统一为 UUID 字符串，前端不对 ID 做数值运算。
- 时间统一 ISO 8601，包含时区偏移，项目按 `Asia/Shanghai` 展示。
- 分页统一 `page`、`pageSize`；默认 `page=1`、`pageSize=12`、最大 50。
- 成功响应统一 `{ code, message, data, requestId }`；`code=0` 表示成功。
- 错误响应也统一该结构；HTTP 状态码与业务码按 API 文档。
- 枚举值一律使用大写英文常量，UI 再翻译成中文。
- 前端显示文本用中文，不把数据库枚举原样暴露给用户。

## 7. 安全与隐私规则

1. 密码只存 bcrypt 哈希；任何 API 响应不得返回密码或哈希。
2. Token 通过 `Authorization: Bearer <token>` 传递，前端存 `sessionStorage`，不存明文密码。
3. 登录、发布、修改、申请和管理接口必须服务端鉴权；仅隐藏前端按钮不算权限控制。
4. 列表和公开详情不返回电话、邮箱等个人隐私。
5. 只有申请双方在必要业务场景中查看申请内容；申请详情不能被第三方访问。
6. 图片只允许 JPG/JPEG/PNG/WEBP，单张不超过 5 MB，最多 5 张；服务端检查 MIME 和扩展名。
7. 首版不做即时聊天；双方通过申请详情中的 `details` 与发布者处理时填写的 `reviewNote` 交换必要信息。`reviewNote` 仅申请双方可见，发布者可自行决定是否在接受申请后提供联系方式；不得公开展示手机号/邮箱。申请内容不得要求他人公开身份证号、完整学号等敏感信息。
8. 不接受 HTML、SVG、可执行文件作为上传图像。
9. `.env`、数据库密码、JWT Secret、用户上传原图、日志中的 Token 不得提交 Git。

## 8. 接口变更机制

任何接口变更先在 Issue 说明：变更原因、影响页面、请求/响应字段、兼容性和负责人。双方在同一条 Issue 明确同意后，先更新 API Markdown 和 OpenAPI YAML，再改代码。未更新文档的接口变更视为未完成。
