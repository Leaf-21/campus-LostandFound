## 3. 本地开发启动

### 3.1 启动 MySQL

本项目开发机使用 **3307** 端口的独立实例（与系统 3306 实例并存，互不影响），**不设开机自启**：

```powershell
# 开发前启动（幂等，已在运行则跳过）
powershell -ExecutionPolicy Bypass -File D:\dsh_project\.tools\start-mysql-lf.ps1

# 结束开发后可选停止
powershell -ExecutionPolicy Bypass -File D:\dsh_project\.tools\stop-mysql-lf.ps1
```

首次建库：

```sql
CREATE DATABASE campus_lost_found      CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE campus_lost_found_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3.2 启动后端

```bash
cd backend
npm ci
cp .env.example .env      # 按需修改 DATABASE_URL / JWT_SECRET / 密码
npm run prisma:generate
npx prisma migrate deploy # 应用全部迁移
npm run prisma:seed       # 写入演示数据（幂等）
npm run dev               # http://localhost:3000
```

验证：`curl http://localhost:3000/health` → `{"code":0,...,"status":"UP"}`

### 3.3 启动前端

```bash
cd frontend
npm ci
cp .env.example .env
# 联调真实后端：VITE_USE_MOCK=false，VITE_API_BASE_URL=http://localhost:3000/api/v1
npm run dev               # http://localhost:5173
```

## 5. 容器化部署

### 5.1 准备

```bash
cp .env.docker.example .env.docker
# 编辑 .env.docker：MYSQL_ROOT_PASSWORD / JWT_SECRET / ADMIN_PASSWORD / DEMO_USER_PASSWORD
#                 CORS_ORIGIN / PUBLIC_BASE_URL 改成真实域名
```

### 5.2 构建并启动

```bash
docker compose --env-file .env.docker up -d --build
```

包含两个服务：

| 服务 | 说明 |
|---|---|
| `mysql` | `mysql:8.4`，**不对外暴露端口**（仅容器网络内可见），数据卷 `mysql-data` |
| `backend` | 多阶段构建产物，映射 `${BACKEND_PORT}:3000`，上传目录卷 `uploads` |

### 5.3 首次初始化数据库

容器启动后需显式执行迁移与 Seed（**不在启动脚本中自动执行**，避免误操作生产数据）：

```bash
docker compose --env-file .env.docker exec backend npx prisma migrate deploy
docker compose --env-file .env.docker exec backend npm run prisma:seed
```

### 5.4 验证

```bash
curl http://localhost:3000/health
docker compose --env-file .env.docker ps      # 两个服务应为 healthy
```

## 6. 生产部署（不用 Docker）

```bash
cd backend
npm ci
npx prisma generate
npm run build
npx prisma migrate deploy
npm run prisma:seed        # 仅首次
NODE_ENV=production node dist/server.js
```

建议用 pm2 或 systemd 托管进程；前端 `npm run build` 后将 `dist/` 交给 Nginx 托管，并把 `/api` 反向代理到后端 3000 端口。

## 7. 运维要点

| 项 | 说明 |
|---|---|
| 上传目录 | `backend/uploads/`，**必须持久化**（容器用 `uploads` 卷）；不提交仓库 |
| 数据库备份 | 定期 `mysqldump`；`mysql-data` 卷为数据落点 |
| 日志 | 生产只输出错误级；不记录 Token / 密码 / 个人隐私字段 |
| 迁移 | 生产只用 `prisma migrate deploy`，**禁止 `migrate dev`** |
| 健康检查 | `/health` 不依赖数据库，可直接用于探针 |
