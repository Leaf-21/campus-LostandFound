# 10｜环境配置与部署说明

## 1. 必备环境

- Node.js 26 LTS（前端和后端共用）。
- npm（随 Node 安装）。
- MySQL 8.4 LTS。
- Git。
- 推荐编辑器：VS Code。
- 推荐浏览器：Chrome 或 Edge 最新稳定版。

两位成员使用相同 Node 主版本和依赖锁文件。Node 版本可用 `.nvmrc` 固定为 `26`，安装依赖统一使用 `npm ci`。

## 2. 服务地址

- 前端：`http://localhost:5173`
- 后端：`http://localhost:3000`
- API：`http://localhost:3000/api/v1`
- 健康检查：`http://localhost:3000/health`
- 上传文件：`http://localhost:3000/uploads/<filename>`
- MySQL：`127.0.0.1:3306`

## 3. 环境变量

### frontend/.env.example

```env
VITE_API_BASE_URL=http://localhost:3000/api/v1
VITE_USE_MOCK=true
```

前端完成真实联调后，把本地 `.env` 的 `VITE_USE_MOCK` 改成 `false`。`.env.example` 只放示例，不放秘密。

### backend/.env.example

```env
NODE_ENV=development
PORT=3000
API_PREFIX=/api/v1
DATABASE_URL=mysql://root:change_me@127.0.0.1:3307/campus_lost_found
JWT_SECRET=replace_with_at_least_32_random_characters
JWT_EXPIRES_IN=2h
CORS_ORIGIN=http://localhost:5173
UPLOAD_DIR=uploads
MAX_FILE_SIZE_MB=5
ADMIN_ACCOUNT=admin
ADMIN_PASSWORD=change_this_before_seed
DEMO_USER_PASSWORD=Passw0rd!
PUBLIC_BASE_URL=http://localhost:3000
TEST_DATABASE_URL=mysql://root:change_me@127.0.0.1:3307/campus_lost_found_test
```

本地创建 `backend/.env` 并修改数据库密码、JWT_SECRET 和管理员密码。真实 `.env` 永远不提交。

> **端口 3307 说明**：本项目开发机使用**独立 MySQL 实例**跑在 3307（数据目录
> `D:\dsh_project\.tools\mysqldata-lf`），与系统默认 3306 实例互不影响。
> 启动/停止脚本在 `D:\dsh_project\.tools\start-mysql-lf.ps1` / `stop-mysql-lf.ps1`，
> 已加入开机启动项。若改用默认 3306 实例，把两处 `DATABASE_URL` 的 `3307` 改回 `3306` 即可。

## 4. 本地初始化步骤

### 4.1 数据库

```sql
-- 开发库
CREATE DATABASE campus_lost_found
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
-- 测试库（npm test 专用，避免污染开发数据）
CREATE DATABASE campus_lost_found_test
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

本项目开发机 MySQL 运行在 **3307**：

```bash
# Windows PowerShell
powershell -ExecutionPolicy Bypass -File D:\dsh_project\.tools\start-mysql-lf.ps1
powershell -ExecutionPolicy Bypass -File D:\dsh_project\.tools\stop-mysql-lf.ps1
```

### 4.2 后端

```bash
cd backend
npm ci
cp .env.example .env
# 编辑 .env，填入本机数据库和密钥
npx prisma generate
npx prisma migrate dev
npx prisma db seed
npm run dev
```

后端初始化后访问 `http://localhost:3000/health`，确认返回健康状态。

### 4.3 前端

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev
```

浏览器打开 `http://localhost:5173`。

> 脚本名称以实际 package.json 为准；初始化当天由对应负责人写入并同步 README。不要仅在聊天中提供启动命令。

## 5. 图片上传

- 本地文件存于 `backend/uploads/`。
- 后端将该目录映射为 `/uploads` 静态访问路径。
- 上传成功后 API 返回可访问 URL；前端发布时只提交 URL 数组。
- 上传目录创建 `.gitkeep`，真实上传文件不提交仓库。
- 部署环境若使用临时磁盘，需确认持久化目录；课程演示可先使用服务器本地持久化目录。

## 6. 部署建议

优先选择一台能同时运行 Node 服务和 MySQL 的云主机/实验室服务器，或分别部署前端静态站点和后端服务。部署方案不影响 API 契约：

- 前端构建产物 `frontend/dist` 部署到静态 Web 服务。
- 后端运行 `npm run start`（以项目脚本为准）。
- MySQL 只允许后端访问，不公开数据库端口给浏览器。
- 配置生产 `DATABASE_URL`、`JWT_SECRET`、`CORS_ORIGIN`、上传目录。
- HTTPS 环境使用 HTTPS API 地址；前端 `VITE_API_BASE_URL` 在构建时写入。
- 迁移使用 `npx prisma migrate deploy`，不要在生产环境使用 `migrate dev`。

- [ ] API `/health` 正常。
- [ ] 登录、发布、上传图片和申请主流程通过。
- [ ] 上传的图片刷新页面后仍可访问。
- [ ] CORS 仅允许配置的前端域名。
- [ ] 管理员密码和 JWT Secret 已更换为独立安全值。

- [ ] 部署日志不输出密码、Token 或敏感个人信息。
