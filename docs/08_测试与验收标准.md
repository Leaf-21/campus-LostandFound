# 08｜测试与验收标准

## 1. 测试原则

本项目验收不仅检查功能是否存在，还检查用户能否自然完成任务。必须覆盖功能正确性、权限与状态、异常反馈、视觉一致性和真实交互流程。

## 2. P0 功能测试清单

### 认证

- [ ] 注册成功；重复账号被拒绝。
- [ ] 账号或密码错误时提示统一，不透露具体字段。
- [ ] 登录后导航栏显示用户状态；退出后清理会话。
- [ ] 未登录访问发布/个人中心时被引导登录。

### 信息列表和搜索

- [ ] LOST/FOUND 切换正确。
- [ ] 关键词可搜索标题和描述。
- [ ] 分类、地点、状态和排序生效。
- [ ] 筛选变化重置页码；清空筛选恢复默认列表。
- [ ] 分页的总数、页码和结果一致。
- [ ] 无结果时显示可操作空状态。

### 发布和详情

- [ ] 必填字段和长度校验正确。
- [ ] 图片支持 JPG/JPEG/PNG/WEBP，单张 ≤5 MB，最多 5 张。
- [ ] 图片能预览、删除；上传失败能重试。
- [ ] 发布成功后详情展示字段正确。
- [ ] 只有发布者可编辑自己的 OPEN 信息。
- [ ] 非发布者不能看到编辑管理按钮；游客点击主操作会登录引导。

### 申请和状态流转

- [ ] FOUND 只能申请 CLAIM，LOST 只能提交 CLUE。
- [ ] 不允许给自己的信息提交申请。
- [ ] 同用户对同信息不能重复提交有效申请。
- [ ] 接受/拒绝申请仅发布者可操作。
- [ ] 接受申请后 Post=PROCESSING，Application=ACCEPTED；其余 PENDING 自动 REJECTED。
- [ ] 完成交接后 Post=RESOLVED，Application=COMPLETED。
- [ ] 已完成、已关闭、已隐藏信息不能新申请。
- [ ] 快速重复点击不会产生重复记录或双重状态变更。

### 个人中心

- [ ] 我的发布、我提交的申请、我收到的申请分区正确。
- [ ] 状态、对应信息标题、时间显示正确。
- [ ] 点击条目可跳转详情。
- [ ] 处理申请后列表状态及时刷新。

## 3. 权限测试

| 场景 | 预期 |
|---|---|
| 游客发布 | 401，前端引导登录 |
| 普通用户编辑他人信息 | 403 |
| 普通用户处理他人信息收到的申请 | 403 |
| 用户申请自己的信息 | 403 |
| 访问不存在的信息 | 404 |
| 已失效 Token | 401，清理本地登录状态 |
| 普通用户访问管理员接口 | 403 |

## 4. 视觉/交互验收（重点）

- [ ] 首页 5 秒内能看懂平台用途，并找到“寻找物品/发布信息”入口。
- [ ] 导航层级清楚，当前页有明确选中状态。
- [ ] 页面最大宽度和网格合理，无横向溢出。
- [ ] 卡片信息层级清晰，图片比例统一，状态标签易辨认。
- [ ] 搜索、筛选、排序有明确反馈，筛选条件可视化并可撤销。
- [ ] 详情页主操作明显，不与次要信息争夺注意力。
- [ ] 发布表单有字段级校验、上传进度、成功/失败反馈。
- [ ] 接受/拒绝/完成等状态变更有二次确认和结果反馈。
- [ ] Loading、Empty、Error、Success、Disabled 状态完整。
- [ ] 按钮命名使用业务动词；无“点这里”等含糊指引。
- [ ] 颜色、字体、圆角、阴影、间距和图标风格一致。
- [ ] 1366×768 和 1440×900 桌面视口无布局错乱；390×844 手机视口可完成核心操作。
- [ ] 表单焦点、错误提示和点击区域可辨认。

## 5. 回归测试演示脚本

**用例 A：招领—认领闭环**

1. A 登录并发布一条 FOUND 信息。
2. 游客进入信息广场搜索并查看详情。
3. B 登录，提交 CLAIM 申请。
4. A 在个人中心查看并接受申请。
5. A 确认完成归还。
6. 确认信息和申请状态都变为已完成。

**用例 B：寻物—线索闭环**

1. A 发布 LOST 信息。
2. B 提交 CLUE。
3. A 拒绝无效线索或接受有效线索。
4. 检查状态、权限和列表刷新。

**用例 C：筛选交互**

1. 在信息广场选择 FOUND、证件卡类、关键词“校园卡”。
2. 检查结果数量和筛选 Chip。
3. 删除一个 Chip，确认仅对应条件被清除。
4. 点击清空筛选，确认恢复初始结果。

## 6. 缺陷等级

- S0 阻断：无法启动、无法登录、主流程数据丢失、越权访问、数据库无法写入。必须修复。
- S1 严重：核心页面不可用、主流程关键按钮失效、错误状态流转。必须修复。
- S2 一般：非核心功能问题、布局错位、响应不一致。尽量修复。
- S3 轻微：小幅视觉偏差、非关键文案。时间允许修复。
